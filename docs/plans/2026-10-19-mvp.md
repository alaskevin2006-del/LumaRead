# LumaRead MVP Implementation Plan

> For agentic workers: use superpowers:executing-plans task-by-task; independent final review before release.

**Goal:** Deliver the approved student reading/recording/check-in and administrator resource/account workflows with isolated deployment and GitHub delivery.

**Architecture:** Next.js client and FastAPI API, PostgreSQL, durable database-backed worker for PDF and evaluation jobs, private media store, evaluator adapters. Docker Compose project `lumaread` has its own network, volumes, resource limits and loopback app port. Never change Yixue/AUGENBLICK source, volumes or containers.

**Tech Stack:** Next.js/React/TypeScript; FastAPI/SQLAlchemy/Alembic; PostgreSQL; PyMuPDF/FFmpeg; Docker.

**Spec:** `产品基线_v1/01_产品基线.md`, `02_UI与交互规范.md`, `03_评分复用与样例方案.md`.

## Global constraints

- Student/admin authorization on the server; forced first password change, disable revokes sessions.
- Published versions immutable; old reading sessions retain their version; archived books prohibit new sessions only.
- Valid scored attempt completes a page regardless of numerical score. No speech/unrelated/failed evaluation does not.
- Unique check-in per Shanghai local date. Replay creates a new session; retries are idempotent.
- Student providers never silently use Mock. No secret or user audio enters Git.
- Existing server project code and services must remain untouched. Record before/after health and use additive deployment only.
- User explicitly approved the complete product and requested execution/deployment/push; no additional design approval round is required. Target actual hyperlink `alaskevin2006-del/LumaRead`, not its mismatched visible label.

## Review focus

1. IDOR: cross-user session, audio, jobs and unpublished media must be inaccessible.
2. Concurrent retries/completion: uniqueness and transaction behavior must survive duplicate requests.
3. Partial/malformed PDF and audio: bound bytes/pages/duration, isolate failures and retain drafts.
4. Publishing while editing: prevent mutation of historical page content and invalidate calibration checks after edits.
5. HTTPS microphone and service coexistence: do not replace existing default host or restart unrelated containers.

## Acceptance

Admin can create student, upload/edit/preview/publish/archive/revise a book; student can change password, hear actual audio, record, receive actual-provider feedback, retry, resume, finish and see unique daily check-in. Disable/reset revokes sessions. Published history survives revisions. Reboot/restart preserves data and jobs. Existing sites remain available. No mock score is represented as production evaluation.
