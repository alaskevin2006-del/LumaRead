# 评分复用与样例验证方案

调研日期：2026-10-19。仅完成文档核查，没有运行模型、测量效果或接入账户。

## 决策

采用“已有评分能力 + LumaRead 适配层”。先验证 OpenPronounce；Azure 作为效果对照和可选商业替代；GOPT 保留为研究备选。不自研训练算法，不在尚未测儿童样例时承诺某个开源项目可直接上线。

“直接复用”指保留来源、许可与修改记录，固定依赖版本，封装服务边界。仓库能下载，不等于代码、模型、数据、音频生成依赖都拥有同一许可。

## 候选对比

| 候选 | 官方可核查信息 | 接入判断 | 本版结论 |
|---|---|---|---|
| [OpenPronounce](https://github.com/Halleck45/OpenPronounce) | 英语发音评估，MIT；提供总分、音素与错误单词反馈；README 提醒儿童及噪声会降低识别质量 | 接近可自托管服务，但不能假定其错误置信度就是逐词百分制得分 | 第一候选，样例通过再采用 |
| [GOPT](https://github.com/YuanGongND/gopt) | 官方论文实现，BSD-3-Clause；词、音素、句子多层评分；自有音频推理涉及 GOP 特征链路，仓库提示推理教程存在已报告问题 | 研究代码不是开箱即用产品 API，工程与验证成本更高 | 不作为首版默认 |
| [Azure Pronunciation Assessment](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment) | 官方提供参考文本的发音评估与词级反馈 | 商业服务，需实际区域、账户、配额、费用与数据传输条件验证 | 可选对照/替代，不要求默认购买 |

OpenPronounce [MIT 许可原文](https://github.com/Halleck45/OpenPronounce/blob/main/LICENSE)允许按条款复用，需保留版权及许可声明。GOPT [许可](https://github.com/YuanGongND/gopt/blob/master/LICENSE)与其模型、声学前端和数据资源需分别登记。以上不是对全部传递依赖的许可审计。

## 产品接口契约

请求由学生提交 page_id、session_id、音频和幂等标识；标准文本、版本、口音参数由后端读取。

统一结果：

```text
status: succeeded | unscorable | failed
overall_score: 0..100 或 null
accuracy / fluency / completeness: 0..100 或 null
words[]:
  token_index / char_start / char_end / text
  score: 0..100 或 null
  level: green | orange | red | unknown
  status: assessed | omitted | uncertain
provider / provider_version / scoring_config_version
quality_reason: no_speech | unrelated | poor_audio | alignment_failed | null
```

标准文本原始大小写、标点、重复词顺序要保留；标点不独立评分。单词坐标由后端统一 tokenization 和对齐产生。省略与不确定不同：明确漏读可低分，不确定不能按零分处理。

缺少维度分则返回 null，管理端显示“未提供”。不允许把识别置信度、错误概率、词错误率直接乘 100 后冒充准确度或流利度。仅有全文相似度不满足正式词级反馈要求。

OpenPronounce 如果无法通过有依据的逐词评分映射与样例验证，保持实验 Provider 身份；不得为了统一 UI 人工补造全部单词的高低分。正式默认 Provider 必须有经验证的全词覆盖、数值定义与不确定处理。

## 样例准备建议

用户已经在准备样例；以下清单可辅助补齐，不要求重复制作。

第一轮建议 2–3 本短绘本、每本 4–12 个练习页。每本提供 PDF、封面、标准英文文本、标准原音；整书音频附每页起止时间，没有时间表时管理员手动标注。

建议先准备至少 30 条、来自至少 5 位目标年龄学生的化名录音，条件允许再扩大。包含自然正确读、明显错词、漏词、重复词、慢读和长停顿、短功能词、不同口音、轻微噪声、静音、无关句子。正确读不能只用成人或合成语音替代。

样例登记字段：sample_id、年龄段、book/page、reference_text、audio_path、设备/浏览器、环境、人工总体等级、明确错词位置、人工不确定位置、备注。不采集不必要的真实姓名。

校准集与最终检查集按学生分开，避免同一个孩子的声音同时参与阈值调整与效果宣称。教师至少复核正确读、错误读和模型不确定样例；有分歧的词单列，不拿来强行证明模型准确。

## 验证与采用门槛（拟定目标，非实测）

| 项目 | 检查方法 | 试用目标 |
|---|---|---|
| 输出完整 | 全部标准词均有位置与状态 | 100%，允许明确 unknown |
| 明显无效音频 | 静音/无关/损坏样例 | 不出误导高分，不算完成 |
| 正确词误报 | 教师认可正确词中，被标红比例 | ≤10%，同时报告样本量 |
| 明显错误检出 | 教师确认错词中，橙/红的比例 | ≥70%，不确定样例另计 |
| 总体趋势 | 正确、部分错误、严重错误配对比较 | 大多数符合人工排序，不要求单个绝对分精确 |
| 延迟 | 实际部署硬件、并发 5 条、10–30 秒录音 | 热启动 p95 ≤15 秒；冷启动单独报告 |
| 移动兼容 | iOS Safari、Android Chrome、微信内置浏览器 | 前两者首版必须通过；微信内置浏览器若受限需明确引导 |

30 条仅用于筛选，不足以证明适用于所有儿童。误报与检出必须一起看，不能把所有词标绿以满足低误报。未达门槛优先换 Provider 或收窄支持内容，避免反复自研算法阻塞产品。

## 接入步骤（下一阶段，尚未执行）

1. 固定候选仓库 commit、依赖和权重，记录运行硬件及许可清单。
2. 在隔离环境跑同一批音频，保存原始输出、耗时和错误类型。
3. 编写适配映射，检查词序、漏词、标点及重复词；不混用置信度和分数。
4. 教师盲看样例并复核，按上述门槛比较；若使用商业对照需先配置账户。
5. 选一套 Provider + 阈值版本投入小规模机构试用，保留切换能力。

若没有候选达到儿童试用要求，产品可继续做录音与阅读联调，但不得宣称正式评分已经可用，也不得将 Mock 暴露为真实成绩。
