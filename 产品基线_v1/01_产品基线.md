# LumaRead 产品基线 v1.0

版本日期：2026-10-19。状态：供评审的完整方案，尚未实施。适用范围：一家机构的首版产品。

## 1. 产品定义与依据

LumaRead 是机构提供给学生使用的英语绘本听读、跟读与打卡工具。管理员维护教学资源，学生按页听、读、获得反馈，并积累阅读记录。

已确认：机构场景；使用者大部分低于初中；需要管理员账号与教学资源管理页面；本轮仅交付产品方向、UI、规则与方案；评分优先复用已有项目；用户另行准备测试样例。

参考：用户提供微信小程序短链 `#小程序://英语打卡/iVGiFtxpXjiACxi`。当前未能打开，其具体布局与功能未验证。此方案不是对该小程序的已验证复刻。

本版设计假设：小学阶段为主，兼容低龄学生由家长陪同；先提供手机 Web，平板与桌面可用；账号由机构分配；单机构部署；首发使用美式英语资源。以上不是用户已确认的合同要求，后续可调整。

## 2. 方向选择

| 方向 | 优点 | 代价 | 本版决定 |
|---|---|---|---|
| 学生练习 + 内容管理 | 主线短，方便机构先试用 | 没有完整教学管理 | 采用 |
| 班级作业 + 教师批改 | 能跟踪班级任务 | 角色、任务、截止规则显著增加 | 后续再议 |
| 综合课程平台 | 可容纳课程与运营 | 超出当前问题 | 不采用 |

成功不是让学生刷高分，而是让学生可以独立完成一次短绘本练习，管理员可以持续上新资源。评分为练习反馈，不代表英语能力等级。

## 3. MVP 边界

纳入：机构分配账号；登录与修改密码；绘本库与等级筛选、书名搜索；详情；逐页图片、文本和原音；录音与逐词反馈；重读；续读；完成反馈；自动打卡；学习记录；账号管理；PDF 导入；逐页内容编辑；音频区间配置；预览与发布、下架；评分测试。

不纳入：班级、作业、教师点评、家长独立账号、多孩子切换、多机构 SaaS、付费订阅、聊天、排行榜、积分兑换、自动课程推荐、强制 OCR、自动切音频、自由对话、离线阅读、微信登录、原生小程序实现。

不增加“收藏”和“分享成绩”入口。先解决原需求，不因示意图上出现装饰图标扩大功能范围。

## 4. 角色与权限

| 角色 | 允许 | 限制 |
|---|---|---|
| 学生 User | 浏览发布绘本、练习、自己的进度和记录、修改自己的密码 | 不可查看他人记录或管理资源 |
| 管理员 Admin | 管理资源与学生账号、测试评分、以预览模式查看学生页面 | 预览不产生成绩和打卡；无班级教学报表 |

管理员必须独立账号登录，后端逐请求校验角色。隐藏入口不是鉴权。录音及成绩接口校验所有权；标准文本从已发布页面读取，客户端不可自传以替换题目。

账号方案：管理员创建登录名和临时密码，首次登录必须改密；学生忘记密码联系机构重置。学生不必提供邮箱或手机号。停用账号撤销会话且禁止新登录，历史记录保留。首位管理员在部署时初始化，普通管理员不可随意提权；首版账号页面管理学生，不管理管理员授权。

## 5. 信息架构

学生底部导航只有：**首页 / 绘本 / 我的**。阅读流程隐藏底部导航，避免误离开。

```text
登录 → 首次改密（按需） → 首页
首页 / 绘本库 → 绘本详情 → 阅读
阅读：待录音 → 录音中 → 处理中 → 评分结果 → 重读或下一页
最后一页 → 完成检查 → 完成本书 → 我的学习
我的 → 阅读记录 / 月历 / 账号设置

管理登录 → 教学资源列表
资源列表 → 新建导入 → 页面编辑 → 发布检查 → 发布
资源列表 → 下架 / 编辑副本 / 预览
导航 → 学生账号 / 评分测试
```

## 6. 关键业务规则

### 6.1 什么算完成

绘本分为封面/展示页和练习页。展示页可以无文本、无音频，不计完成分母；每本至少有一页练习页。练习页必须有图片、英文标准文本和有效原音。

每页至少有一次**成功得到有效评分**的跟读记录，即为该轮阅读“已练习”；不设及格门槛。单词漏读可得到低分，但整段静音、文件损坏、完全无关文本、严重无法对齐归为无效录音或无法评分，不算已练习。具体质量判定由样例验证，不能只看识别文字是否相似。

允许随时翻页和只听；跳过的页仍为未练习。末页点击“完成本书”时，服务端检查所有必读练习页：齐全则完成；不齐全展示缺页清单，进入第一张未练习页。翻到末页本身不算完成。

评分暂不可用仍允许听读和翻页，不伪造通过记录；明确标记未评分，服务恢复后可重新提交/录制。首版不开放学生自报完成，避免完成语义不一致。

### 6.2 重读与续读

同一页每次重读新增 attempt，不覆盖旧录音和分数。结果页显示本页本轮最近一次成功评分；新重读失败时保留旧成绩，并提示“这次未评分，显示上次结果”。本次失败不会撤销已经获得的页完成状态。

退出后恢复本轮最后浏览的页；录音原始数据不承诺跨关闭浏览器恢复。已完成的书提供“再读一遍”，明确新建一轮 session，旧轮次完整保留。未完成的一轮不能重复新开，默认继续。

### 6.3 打卡与统计

一次阅读轮次满足全部练习页，并被服务端确认完成，自动打卡。一天完成多本只记一天；同一本新的一轮在另一天完成也可以打卡。

日期以机构时区 Asia/Shanghai、服务端完成时间计算，不信任设备时钟。跨午夜以最终完成时刻为准；不补签、不因仅听原音或打开页面打卡。

“已读绘本”是至少完成一轮的不同绘本数量；“完成次数”是完成轮次数，两者不得混用。连续天数：今天已打卡从今天倒推，否则从昨天倒推；若昨天也未打卡则为 0。日历可切换月份，不展示未来打卡。

### 6.4 评分呈现

学生只看到页总分 0–100 和原文逐词状态。准确度、流利度、完整度在评分测试页查看，学生端不堆三个维度仪表盘。

初始颜色阈值仅为待样例校准的默认配置：green ≥80；orange 60–79；red <60。未知/不可靠为灰色，不能强行判红。橙色加虚线、红色加实线下划线，使反馈不只依赖色觉；低分文案“先听一遍，再试试”，不出现失败、淘汰或同伴排名。

后端按标准文本 token 顺序定位，包括重复单词；标点保留原样、不评分。没有逐词数值的 Provider 不能用错误置信度直接冒充单词分数。首次使用只给一次简短图例，日常页面不重复大段解释。

### 6.5 阅读与录音

原音为单页音频或整书指定区间。听原音与录音互斥，开始录音前停止播放；翻页停止上一页播放。录音由学生主动开始、主动停止；停止后自动上传评分。

暂定每页录音最多 60 秒，45 秒提示余时，60 秒自动停止提交；每页建议不超过 45 个英文词。超长页由管理员人工拆分或调整，不默默截断标准文本。支持录音格式按浏览器协商，再由服务端统一转码，不假定所有手机都产出 WebM。

首次点击录音时才请求麦克风权限。录音中退出/翻页需确认“放弃这次录音”；处理中允许离开，已上传的任务继续，返回时同步。网络重试复用请求标识避免重复成绩。录音中切后台/来电中断时停止并提示重录，不将残缺内容作为正常提交。

加载动画不用虚假的百分比。评分 15 秒后提示“还在处理中”，60 秒超时进入可重试状态；这两个是体验设计默认值，不是已测性能。原音失败只禁用播放并给重试，仍可跟读。

## 7. 内容生产与发布

流程：新建书目信息 → 上传 PDF → 后台分页与提取文本 → 逐页校对 → 上传音频 → 指定每页文件/整书起止区间 → 学生视角预览 → 发布检查 → 发布。

文本自动提取不等于已校对；图片 PDF 可手动录入，不强制 OCR。PDF 处理是后台任务，显示真实处理页数、失败原因和重试入口；导入失败不删除已有草稿。

书目信息：标题、可选中文简介、封面、等级、内容状态。等级 A/B/C 是机构内部标记，不宣称对应 CEFR/考试标准。首版默认美式英语，混合口音资源在正式接入评分前另行明确支持范围。

每页：图片、页序、页类型（展示/练习）、标准文本、音频模式、音频文件或起止毫秒。整书音频要求 0 ≤ start < end ≤ 文件时长；可试听区间；允许多页共享文件但不自动推断切点。

暂定上传限制：PDF ≤50 MB / 100 页；音频 ≤100 MB；限制可配置。练习页超过建议词数显示警告并要求人工确认拆分；处理失败明确指向页码。

发布硬检查：标题和等级完整、封面存在、至少一练习页、所有练习页的图片/文本/音频可用、区间合法、每页校对确认完成。未通过不能发布。

状态：draft → published → archived。发布前可改草稿；发布后学习内容锁定。修改发布书籍时创建修订草稿，发布后产生新版本；旧轮次继续引用原版本，避免文本/页码错位。首版可以同一 Book 下新建不可变 BookVersion 实现，禁止直接覆盖已被使用的 Page。

下架从学生书库隐藏并禁止新开轮次；已有轮次可继续访问对应旧版本。紧急撤回因内容原因需禁止访问时，另作显式撤回操作，不以普通下架替代。首版不实现紧急撤回 UI，可由运维按记录执行。仅无学习记录的草稿可删除；已发布或有历史的数据使用下架。

## 8. 视觉与交互基线

风格：安静、清晰、轻快的阅读工具，插画提供亲和感，控件保持成熟；不采用满屏卡通贴纸和幼儿化文案。

学生主色为深青绿，奶油白背景，橙色用于录音动作和点缀；正文深墨色。错误红与录音橙区分。大字号英文、44 px 以上触控目标；正文可纵向滚动，操作区固定且不遮挡文本。管理员使用同一色系的桌面布局、侧栏、表格与三栏编辑器。

设计稿使用原创示例插画与虚构学生数据。示例书名、文本、成绩只用于展示，不是已导入内容。正式绘本以机构提供素材为准。

详见 `02_UI与交互规范.md` 与 `UI/index.html`。图文冲突时：业务规则以本文件为准，精确文案和状态以 UI 规范为准；图片不是后台行为的唯一依据。

## 9. 技术方案边界

沿用 Next.js / React / TypeScript / Tailwind 的前端方向，FastAPI 负责业务与评分适配，PostgreSQL + SQLAlchemy + Alembic 负责数据，PyMuPDF 处理 PDF，FFmpeg 负责音频。此处为方案选择，未安装依赖、未验证兼容性。

业务 API、媒体处理任务、评分运行时分离。MVP 为模块化单体加后台任务进程，不拆大量微服务；评分可调用隔离部署的开源服务，也可调用商业 API。API 不同步等待 PDF 全部处理结束；评分采用任务标识查询结果，支持幂等重试。

媒体文件：开发本地，生产私有对象存储；使用授权地址，成绩、学生录音不暴露为永久公开 URL。数据库保存资源引用，不存大块音频。

核心对象：User、Book、BookVersion、Page、MediaAsset、ImportJob、ReadingSession、ReadingAttempt、EvaluationJob、Checkin。轮次固定 book_version_id；成绩固定 page_id、reference_revision、provider_version、scoring_config_version；Checkin 对 user_id + local_date 唯一。页面结果是历史记录的读取视图，不是覆盖式存储。

前端不直接持有评分服务密钥；Provider 原始返回只在管理员测试场景可见。Mock 仅用于开发联调，必须标“模拟评分”，不得作为正式学生成绩。

## 10. 数据使用默认方案

录音只用于本次练习评分和必要复核，不默认用于模型训练或公开分享。家长/机构在启用录音前能够了解用途和保留期限，最终告知方式由机构确认。首次录音提示与账号设置提供对应说明入口。

建议录音保存 30 天后删除，文字成绩与进度在账号有效期间保留；管理员重置/停用账号不等于删除数据。设置页提供联系机构处理数据删除的方式，首版由机构受理，非自动删除按钮。测试样例使用化名，不把真实姓名加入文件名；这些是产品默认建议，不是法律结论。

## 11. 验收场景与后续顺序

1. 管理员创建学生，首次登录改密，学生无法访问管理资源接口。
2. 一份有文本层 PDF 和一份扫描 PDF 均可生成可编辑草稿；分别验证单页音频与整书音频。
3. 未补齐音频的练习页阻止发布；发布后可从学生端搜索并阅读。
4. 原音、录音互斥，拒绝麦克风、断网、静音、后台中断都有可恢复状态。
5. 正常跟读得到总分与按位置对应的逐词结果；缺失指标不造数。
6. 重读新增记录，低分不阻断下一页；重读失败不清除上次结果。
7. 跳过一页后不能直接完成，补齐后只生成一次完成事件和当日打卡。
8. 同一天多本、跨日、新轮次、重复回调不产生错误打卡和统计。
9. 下架隐藏新入口，旧轮次可续读；修订发布不会改坏旧成绩。
10. 手机窄屏、长文本、横屏、iOS/Android 录音用真实设备验证。

后续实施顺序：账号与资源闭环 → 学生阅读与 Mock 流程 → 录音与真实评分候选验证 → 完成打卡与异常场景 → 机构试用。每阶段可演示后再推进，本轮不启动实施。

方向已收敛；正式开发前需由机构确认三个部署参数：首发 Web 是否满足使用方式、账号发放和录音告知方式、实际样例的长度与设备。评分 Provider 由样例结果选择，不在此文档里假定已经验收。
